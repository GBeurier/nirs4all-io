Build a dataset specification from tables

Drop delimited text tables (any file name) or load the sample. The nirs4all-io WASM owner decides whether each file is a readable table, inspects the columns, proposes the open decisions and materializes the result; you confirm decisions, map columns and choose the missing-value policy. The exported file is the owner-validated DatasetSpec. Everything runs locally in your browser. Vendor spectral formats are read by the main builder.

loading WASM… Waiting for files.

1. Files

Each file is kept as the exact bytes you provided and sent unchanged to the owner.

2. Decisions to validate

Owner proposals, with uncalibrated scores and evidence. Confirming a decision sends it back to the owner as a lock.

3. Columns

Initial roles come from the owner's proposed specification; where it uses a selector this page does not resolve, the owner's column guess is shown and labelled as a guess.

4. Dataset declarations

Name, missing-value policy, partition column and repeated-measure declarations. Only the owner's vocabulary is offered.

5. Materialized preview

Counts come from the owner's assembled result. Axes, masks and data stay in that result.

6. Export

The exported specification is the owner-validated, canonical DatasetSpec.

The column table is composed from public components of nirs4all-ui; inspection, proposals, materialization and validation are done by the nirs4all-io WASM owner. The owner refuses cross-sample statistical fills (mean, median); only the missing-value policies listed on the page are offered.
